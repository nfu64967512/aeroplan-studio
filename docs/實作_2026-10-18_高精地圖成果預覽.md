# 實作：規劃後預覽「拍完會長怎樣」的高精地圖（2026-10-18～19）

使用者要求：「規劃器跑完區域拍照完後，我們也可以看到預計這區域拍完之後的高精地圖大概會長這樣的樣子。」
本機 vtol 分支、未 commit。只在 HARVEST「航測建圖」模式的規劃結果上啟用。

## 1. 看得到什麼

規劃完成、上傳閘門的狀態顯示之後，背景自動算一份「預計成果」，畫在 2D 與 3D 地圖上：

- **預計成圖範圍**（白框）：每格至少 5 張照片拍到的地方（與上傳閘門同一個門檻），範圍外整片調暗。
- **品質分級上色**（半透明，底圖照樣透出來）：只有 1 張（不會成圖）紅、2–4 張（邊緣、可能缺漏或扭曲）橘、5–8 張（可成圖）黃綠、≥9 張（高品質）綠。
- **破洞**：紅框＝上傳閘門判定的內部破洞（會擋上傳）；紅點線＝只在較細的預覽格看到、閘門沒擋（仍建議檢查）；橘虛線＝邊緣帶張數不足。
- **預計拍照位置**：依機色的小點（超過 5000 張時均勻抽樣，圖例會寫「只畫 N／M 張」）。
- **圖例**：左下，固定寫「規劃預測，非實際成果」；說明條目預設收起。

偵察頁「航測建圖」群組多了「預覽高精地圖成果…」按鈕和「地圖顯示預計成果」勾選框；工具選單也有同名項目。
按鈕打開成果卡（可以一直開著）：

| 項目 | 內容 |
|---|---|
| 地面解析度 | 每張照片依模擬的對地高度算，最小／中位／最大（cm/px） |
| 正射與 DSM | 正射 ≈ GSD；DSM ≈ 2×GSD（ODM 預設的經驗值，標成估計） |
| 張數 | 每架與總數（模型偏樂觀，見假設） |
| 資料量 | 本相機像素數 × 0.6–1.0 B/px 的範圍（未經實測；IMX477 約 7.4–12.3 MB/張） |
| ODM 記憶體 | 依張數查 ODM RAM 表的等級 |
| 面積與視數 | 測區內可成圖、高品質面積；內部與邊緣帶 ≥5／≥9 張的比例 |
| 重疊 | 前向／側向第 5 百分位、跨機接縫最窄 |
| 破洞 | 以上傳閘門（4 m 格）為準；預覽格（2 m）多看到的另列 |
| 精度 | **只列文獻範圍與條件**；我們自己的精度要等檢核點飛過才知道 |
| 看得到什麼 | 以中位 GSD 換算：車道線、交通錐、人孔蓋、機車、小客車各佔幾個像素 |
| 假設 | 與上傳閘門相同（沒模擬 CAM_MAX_ROLL 與轉彎動態 ⇒ 偏樂觀）等 |

「匯出 PNG＋JSON…」存一張示意圖（不是地理參照影像）和一份統計 JSON；預覽過期（計畫已換）時會先問、檔名加 `_stale`。

## 2. 刻意不做的事（誠實原則）

- **不拿衛星底圖假裝成預測正射圖**：那會讓人以為拍完就長那樣，也違反圖資條款。預測的只有「每處會被拍幾張、解析度多少」。
- 精度不給我們自己的數字，只給文獻範圍與條件。
- Cesium World Terrain 的地形不寫到任何檔案（授權只准在記憶體）；地形陰影只在用本機 DEM 時產生。

**順手修的舊錯誤**：2D 地圖的圖層控制項加在疊圖之前，folium 0.20 下只要加照片位姿、GCP 點或正射圖磚，整個 2D 頁就只剩底圖（JS 例外 `setZIndex`）。
已移到最後；有負對照測試。

## 4. 速度

| 情況 | 預覽計算 |
|---|---|
| 測試用真規劃（1.2 km²、1P＋2H、1942 張） | 0.6–0.7 s（另跑 4 m 閘門格） |
| 合成 12 km² 全覆蓋（3 架、約 18,000 張） | 約 3.5 s |

都在背景執行緒，不卡畫面。地圖 payload 約數十 KB 到 1 MB。

## 6. 限制

- 預測沿用曝光驗證器的模型：足跡投到天底地面高度的水平面、沒模擬 CAM_MAX_ROLL 與轉彎動態 ⇒ 張數與接縫偏樂觀（5 m/s 風 SITL 曾從 0.78 掉到 0.32 刈幅）。
- 沒載 DEM 時規劃用 0 m 平面，GSD 會看起來到處一樣。
- 「預計成果」只在 HARVEST 建圖模式出現；如果規劃後跳出「不能上傳」的對話框，要按掉它之後才開始算。
- 整個流程沒有在真的執行中 app 裡從頭點過（測試用真的元件與真規劃，但主視窗是假物件）；第一次在 app 裡用時請留意圖例位置與按鈕狀態。
