## ⚠⚠ 用 NotebookLM 補文獻前必讀

本專案 2026-08-14 有過紀錄在案的事故：NotebookLM 把**我們自己上傳的專案文件**
當成外部文獻引用，並憑空生成我們系統的數字（「兩機 pinned 在 210 m/s」
「784 m 高度差」之類）。那是最貴的一種錯誤 —— 「文獻支持我們的假設」
其實只是我們的假設繞了一圈回來。

用它查文獻時的規矩（沿用既有紀律）：

1. 明確要求**逐字原文 + 出處**；未標「逐字」的一律降級成推論，不可當依據。
2. 看到它引用**我們系統的具體數值**（m/s、秒、公尺）直接當紅旗 ——
   論文不會知道我們的 UAV 飛多快。
3. 式子要連**正負號約定與符號定義**一起取，不要只取摘要。
4. 每一筆都要能在 DOI / 出版商頁面獨立查到才算數。

## 二、必須涵蓋的五類（不分主張，投稿的基本盤）

1. **CPP 綜述與胞分解**：Boustrophedon / 梯形分解的原始工作與後續綜述。
   我們的 `decompose` 直接建在這上面，卻一篇都沒引。
2. **多機覆蓋與區域分割**：DARP 那一系；我們的基準線裡就實作了 DARP 變體，
   卻沒有引用它的原始論文 —— 這在審稿時會被直接點名。
3. **min-max 多機覆蓋 / makespan 最佳化**：我們的目標函式就是 min C_max。
4. **能量受限路徑規劃**：見 A1。
5. **VTOL / 複合翼任務規劃**：這是我們機型的特殊性所在（轉換走廊、
   垂直起降段），也是最可能真的有空白的一塊。

⚠ 第 2 類特別要注意：**我們自己實作了 DARP 當基準線**。實作了別人的方法卻不引用，
是投稿最容易被退的技術性問題之一。

## 三、⚠ 一個需要你確認的範圍問題

你說的 NotebookLM 筆記本叫「**VTOL 群飛編隊規劃**」。

「編隊規劃」（formation flight）和 HARVEST 在做的「**覆蓋路徑規劃**」
是**兩批不同的文獻**：

* 編隊：隊形保持、長僚機、一致性控制、避碰。
* 覆蓋：胞分解、條帶鋪設、區域分割、min-max 分配。

而且本 repo 裡真正在做編隊的是**另一個專案**（STOT / `scripts/wsl/sar_swarm`，
多旋翼長僚打擊），不是 HARVEST。

所以請確認那個筆記本是：

* (a) 給 **HARVEST 覆蓋規劃**用的 → 上面的清單就是缺口；
* (b) 給 **STOT 編隊**用的 → 那要另外列，兩者幾乎不重疊；
* (c) 兩個都要 → 那要拆成兩份，不要混在一起查
  （混在一起正是 [[confirm-direction-not-just-topic]] 那條教訓的來源）。
