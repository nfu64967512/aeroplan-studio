2. THE SEQUENTIAL BASELINE DRIVER (beamidp_table.py)
----------------------------------------------------
  No PlannerConfig can produce a sequential scan.  planner.py:604-605 ranks the
  K-nearest candidates by t_add (transition + operate TIME):
        Kn  = int(min(K, m.size))
        sel = np.argsort(t_add, kind="stable")[:Kn]
  so K=1 only makes the search greedier about SKIPPING; legacy_mode only sets the
  ESTIMATOR's sweep_sequence="fixed".  The sequential arm is therefore EVALUATED,
  not planned.

  cell_ruler() re-implements hv_dccpp/decompose.py exact_time() verbatim up to the
  point where exact_time calls _best_sequence, then forces the order.

  HELD FIXED (bit-identical across all four arms)
    strip set          the Strip objects the planner itself built for that cell
    R_eff              decompose.r_eff_for_class(ctx, cls, z_top_m=z_op)
                       Pioneer 200 m, HERO 120 m at W=5 m/s (unchanged by wind:
                       W* = 5.1675 / 5.0333, see C6)
    wind               ctx.wind.wind_vec(z_op) -- the same vector, full wind triangle
    airspeed           ctx.specs[cls].cruise_airspeed_mps (21.5 / 19.0)
    Dubins integration cfg.dtheta_int_rad
    entry/exit         Strip.end_state(-1|+1) -> Strip.start_state(+1|-1) with the
                       planner's own 0.5/0.5 direction average (1.0 for strips that
                       are one-way feasible).  one_way count was 0 in every cell.
    operate time       decompose._op_times(); order-independent, so it cancels in
                       every delta, and is still shown in "cell mission time"
    energy             EnergyModel.transfer_wh(t, dz = 0) -- the planner's own
                       k_unc * P_cruise * t.  All strips in a cell share z_op, so
                       dz = 0 and this is exact, not an approximation.
                       P_cruise * k_unc : Pioneer 617.5 W, HERO 223.7 W.

  WHAT IT CANNOT CONTROL (stated, not hidden)
    * inter-cell transit, takeoff/entry and RTB legs are re-scheduled by the
      planner.  A truly flown sequential arm would get different ones => every
      makespan figure for the sequential arm is an ESTIMATE.
    * 4-D deconfliction and corridor queueing can insert holds this cost model
      does not see.
    * the direction each strip is actually flown.  The 0.5/0.5 average is the
      planner's estimator convention, so the "Beam-IDP as planned" row is scored
      under the estimator's ruler, not under its own committed directions.
    * takeoff / landing / climb energy: excluded; only in-cell segments compared.
    * CONFIRMED NOT A PROBLEM HERE: every aircraft's tour is cell-contiguous
      (fly_ready.json "contiguous_per_cell": true for A1, B2, B3), so the
      within-cell Beam-IDP sub-tour really is a contiguous chain of n-1
      transitions -- no cross-cell contamination in this table, unlike the
      c3 per-aircraft mixed-fleet numbers.

RISKS AND LIMITS
----------------
  * Every number in section 3 is the PLANNER's cost model (Dubins in a wind
    triangle), not flown telemetry.  SITL has never had wind (C2), so this table
    must never be captioned as a measured in-flight saving.
  * The sequential arm cannot be flown without a driver; only the Beam-IDP arm is
    flyable today.  A flown sortie proves executability, not the saving.
  * The makespan delta (+7.86%) is an estimate; entry/RTB legs are not re-planned.
  * The new scenario changes the GEOMETRY relative to the paper scenario (that is
    the point), so the comparison is "mechanism inactive here / active there", not
    "the flown sortie could have been 34% cheaper".
  * The Pioneer trigger is fragile: it needs a subregion of about 11+ strips.  If
    the fleet ratio or the split strategy changes, this scenario can silently stop
    triggering -- that is why the per-cell n and k are recorded here and not just
    the makespan.
  * skip_k uses the MEAN spacing (decompose.py:825 s_mean); with a single uniform
    camera every strip has the same spacing, so this is invisible here.
  * B2's energy margin is the tightest at 88.7 Wh; it was 89 Wh in the export too.
    Worth watching if the sortie is later flown with wind switched on.
