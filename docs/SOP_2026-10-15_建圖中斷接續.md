# SOP：建圖任務中斷後怎麼接續、哪條帶要補飛（2026-10-15，草案）

> 對應討論文件 A5。程式端：條帶監測器 `survey/strip_monitor.py`、鏈路信號 `mission/sitl_link.py`
> （`mission_current`、`mission_item_started`）。
> ⚠ **草案**：§4 的三件事要你決定；ArduPilot 行為是讀 master 原始碼得到的，**還沒在 SITL 驗過**（§6）。

---

## 1. 為什麼需要這份 SOP

- ArduPlane 預設 `MIS_RESTART=0`（resume）。中斷後切回 AUTO，飛機會從「目前正飛向的航點」接續。
- 在條帶上中斷時，「目前航點」就是**帶終點**，飛機會從當下位置**斜飛**過去。結果：
  - 從中斷點回到帶線之間那段，照片是斜的或拍在帶外；
  - 中斷點到帶終點之間，很可能漏拍。
  - 相機觸發距離寫在 RAM 裡，回到 AUTO 時會自動恢復，**不會有任何警告**。
- `MIS_RESTART=1` 更糟：空中重新進 AUTO 會從第 1 項（VTOL 起飛）**整份重飛**，能量撐不住。任何短暫切模式都會觸發。⇒ **維持 0**。

## 2. 飛前

1. 讀回閘門要包含：
   - `MIS_RESTART = 0`（待接：建議參數與 GUI 讀回）；
   - `CAM_AUTO_ONLY = 1`；
   - `CAM1_TRIGG_DIST = 0`：上一趟中斷留下的殘值會在這裡被抓到；
   - `RTL_AUTOLAND = 2`，以及 `LOG_BITMASK` 含相機。
2. 勾選 tlog。
3. 上傳後記下每架的**條帶段表**（監測器提供）。每段要有：段號、條帶 id、開相機的 seq、關相機的 seq，以及**回接 seq**（`rejoin_nav_seq`＝引入 NAV 的前一個 NAV）。

## 3. 中斷的種類與處置

| 情況 | 監測器警報 | 處置 |
|---|---|---|
| (a) 帶上被操作員或交通暫停（LOITER、QLOITER、GUIDED） | `interrupted`（警告） | ① 送 `DO_SET_CAM_TRIGG_DIST 0`，或把 `CAM1_TRIGG_DIST` 設 0；② 把目前航點設為該段的**回接 seq**（Set WP）；③ 切 AUTO，飛機會重飛進場彎與引入段，206 開會重新執行；④ 監測器應顯示「第 2 次嘗試」，張數開始增加。**禁止中斷後直接切回 AUTO。** |
| (a′) 違反上一列，直接切回 AUTO | `resumed_without_rewind`（嚴重） | 這條帶落地後補飛，或在不影響時程時依 (a) 倒帶重飛。 |
| (b) 失效保護 RTL（電量、圍籬、長時間失聯） | `jumped`，之後各段 `not_flown` | 任務會跳進降落序列，相機已經關了。**不要嘗試接續**。落地後依「未飛／跳走」清單補飛。 |
| (c) 條帶飛完但 0 張 | `zero_photos`（嚴重） | 先看 CAMERA_FEEDBACK 的張數有沒有在動。0 張警報只代表**飛控沒觸發**；沒接熱靴回授腳時，相機端（樹莓派）漏拍地面站看不到。相機確定壞了 ⇒ 中止建圖。暫時性問題 ⇒ 依 (a) 重飛那條帶。 |
| (d) 張數不足（< 預期的 0.8） | `under_count`（警告） | 有風時，CAM_MAX_ROLL 會把觸發延後，所以這多半不是故障。先記下來，比例低於 0.5 才重飛。 |
| (e) 遙測中斷超過 5 s | `unverified_count`（資訊） | 不下判斷，留到飛後用 .BIN 對帳。 |
| (f) AUTO 中有帶外照片 | `off_strip_photos`（警告） | 檢查 206 開關與 `CAM1_TRIGG_DIST` 殘值。 |

## 4. 要你決定的事

1. **群飛時，空中要不要倒帶重飛？**
   - 建圖模式不分高度層，時間錯開是唯一的隔離。空中重飛一條帶會讓這架的時間軸往後延約 1–2 分鐘，可能違反 4D 去衝突。
   - **建議預設**：群飛時只標記、落地後補飛；單機時才允許空中倒帶。
2. **GUI 要不要加「回到條帶 k 起點前」按鈕？**
   - 按鈕送 MISSION_SET_CURRENT，並且要確認才執行。
   - 目前 GUI 沒有 Set WP，只能用 Mission Planner 經 fan-out 埠做。
3. **讀回時發現 `MIS_RESTART ≠ 0`，要怎麼處理？**
   - 選項一：比照相機參數，經你同意後寫成 0；
   - 選項二：只擋下，由你手動改。

## 5. 飛後

- 用 `survey/qa.conservation_table` 與 .BIN 的 CAM 對帳。要**以 `cnum_on` 對應條帶**，不要用序號：地形重發與重飛都會讓 `strip_windows` 多切一窗。
- 再與監測器的逐段張數比對，決定補飛清單。

## 6. 已驗證與還沒驗證的

**已驗證（2026-10-15，SITL `S1_HDMAP_20261015_PW3`）**：正常飛完的三架，監測器以 .BIN 的「Mission: N」與 CAM 重播，逐條帶張數與日誌完全相同、零誤報；並發現最後一條帶飛控會先開始下一個 NAV、0.1 s 後才執行 206(0)（監測器已處理）。

**還沒驗證、要在 SITL 驗的**：

1. 帶上 LOITER 後直接 AUTO：預期回接段有斜照、有漏拍，並出現 `resumed_without_rewind`。另外照 SOP 倒帶飛一次，兩者比較。
2. `CAM1_TYPE=0`：預期出現 `zero_photos`。
3. 觸發失效保護 RTL：預期出現 `jumped` 與 `not_flown`。
4. Plane 接續時，會不會沿原帶線做交叉追蹤。
5. Set WP 指到 206(0) 這個 DO 項目時，會不會直接把相機關掉。
6. 4.5／4.6 板子與 4.8.0-dev 行為是否一致。
