1. WHAT THE TIME COST ACTUALLY COMPUTES  -- full wind triangle, NOT headwind-only
===============================================================================

hv_dccpp/wind.py:278-291  (the single definition of ground speed used everywhere)

    def ground_speed(theta_rad, v_air_mps, wind_xy):
        _, w_par, w_perp = _components(theta_rad, wind_xy)
        rad = v_air_mps * v_air_mps - w_perp * w_perp
        out = np.where(rad > 0.0, np.sqrt(...) + w_par, np.nan)

hv_dccpp/wind.py:271-273  (component decomposition; theta = TRACK bearing, ENU atan2(dx,dy))

        w_par  = wx * st + wy * ct        # w . t_hat   (along-track)
        w_perp = wx * ct - wy * st        # w . n_hat   (cross-track, right normal)

    =>  V_g(theta) = sqrt(V_a^2 - W_perp^2) + W_par          both components, signed.
        Headwind (theta = beta): V_a - W.  Tailwind: V_a + W.  Pure crosswind: sqrt(V_a^2 - W^2).

hv_dccpp/wind.py:294-306  heading_from_track: psi = theta - arcsin(W_perp / V_a)  (crab angle)

Leg times, hv_dccpp/wind.py:370-388 (line) and 390-421 (arc):
        time_line = L / V_g(theta)
        time_arc  = sum_j  R * delta / V_g(theta_j),  midpoint Riemann, delta <= cfg.dtheta_int_rad

Consumers -- every cost in the planner goes through this:
        hv_dccpp/costs.py:81-92    _vg_array   (vectorised copy of the same formula)
        hv_dccpp/costs.py:370-386  op_cost     t = strip.length_m / V_g(theta_dir)
        hv_dccpp/costs.py:388-419  _route_cost t = path_time(path, va, wxy, z_mid)  (transfer / entry / RTB)
        hv_dccpp/costs.py:842+     CostCache   -> hv_dccpp/allocate.py:_chain -> planner makespan
        hv_dccpp/costs.py:95-119   v_air_star  picks V_a* so that V_g <= sensor ground-speed cap

VERDICT: the implementation is a full two-component wind triangle.  The abstract word
"迎風" (headwind) is wrong about the code; the body's "含風地速" is right.  Note both are
also incomplete as descriptions, because V_g feeds BOTH the straight legs and the arc
integral, and V_a itself is re-selected per strip (v_air_star).

    def r_eff(self, wind_speed_mps: float) -> float:

ASYMMETRY (answers "is the wind assumption applied consistently to both?"):
    time cost : wind VECTOR at the leg altitude, direction-dependent, both components.
    R_eff     : wind SPEED only (a scalar max over the layer band), direction-independent,
                then clamped from below by R_plan.
    Same WindField object, two different reductions.  Both are deliberate (R_eff is a
    worst-case bound, the time cost is a per-leg estimate) but the paper currently reads as
    if one wind model produced both.
