## 1. 可直接用於表 2b 表註 (b) 的句子

> (b) `HV4W55S`（規劃風與模擬風皆 5 m/s／180°）的三架機在解鎖前被 SITL 地面模型

> 該位移**不是**沿風向的直線滑移，而是機體以約 0.084 m/s（模擬時間）沿**自身機首方向**
> 前爬、同時因風標效應持續偏航所畫出的**弧線之弦**：逐段位移方位角與該段機首方向的

> 之後所飛的那半段弧，不是另一個向東的力。三架機為**剛體平移**：兩兩間距由規劃的
> 10.008／10.008／20.017 m 變為 10.019／10.019／20.038 m，最大變化 0.022 m，
> 亦即本閘門所要偵測的「規劃分了起降站、SITL 沒分」並未發生。
> 本架次因此以明示的 `HV_SPAWN_TOL_M=6.0` 覆寫執行（預設值仍為 2.0 m，未更動），
> 產物中以 `tol_overridden=true` 留痕。

## 3. 機制（可支持的部分）

### 3.1 位移是**模擬真值**，不是狀態估計假影

`sorties2/HV4W55S_spawn_probe.json`：dataflash 的 `SIM.Lat/Lng`（SITL 自己的真值狀態）
與 `POS.Lat/Lng`（EKF 估計）在解鎖後的第一筆就同時位於 (+3.756 N, +3.553 E) m，兩者差
< 0.05 m。所以閘門讀到的位移是飛機真的在那裡，不是 EKF 漂掉。

### 3.2 前爬方向鎖在**機體 x 軸**，不是風向

`sorties2/HV4W55S_spawn_arc.json`（A1，解鎖前遙測軌跡，11 個位移段）：

| 段末 t (s) | 步長 (m) | 位移方位角 (°) | 該段平均機首 (°) | 殘差 (°) |
|---|---|---|---|---|
| 3.03 | 0.411 | 18.74 | 19.15 | −0.41 |
| 5.06 | 0.407 | 35.10 | 34.65 | +0.45 |
| 8.08 | 0.418 | 55.93 | 55.15 | +0.78 |
| 11.11 | 0.425 | 73.18 | 72.80 | +0.38 |
| 13.13 | 0.419 | 83.98 | 84.25 | −0.27 |

（全部 11 段：殘差中位數 −0.32°、最大絕對值 1.00°。）機首在這段期間由 19.2° 轉到
84.3°，而位移方位角**一路跟著機首走**。若是風把飛機推著滑，每一段的方位角應該固定
在同一個風向上；實測不是。步長固定在 0.407–0.425 m／牆鐘秒（`HV_SPEEDUP=5` ⇒
**0.084 m/s 模擬時間**），觀測到的路徑長 4.648 m、淨位移 4.338 m。
⚠ 軌跡是在鏈路開始輪詢之後才有的：第一筆可用樣本已經在 (+0.989 N, +0.03 E) m，
所以這 11 段沒有涵蓋全部位移；閘門量到的 5.015 m 才是完整值。

### 3.3 偏航是**風標效應**，而且發生在地面上

`sorties2/HV4W55S_spawn_probe.json`（B2，解鎖後停在地面等放行的 445.0 s 視窗，dataflash 真值）：

* `SIM.Yaw` 由 126.91° 單調漸近到 **179.45°** —— 機首指向 `SIM_WIND_DIR=180`（氣象來向），
  即正對著風。這是教科書式的風標收斂。
* `SIM.Alt` 全程固定 100.09 m（地面高度），`SIM.Roll`/`SIM.Pitch` 中位數皆 0.0 ⇒
  整段都在地面上，沒有離地。
* 同一視窗內真值位置只再移動 0.31 m（北）／0.25 m（東）⇒ 機首轉離順風之後，前爬就停了。
  這同時解釋了「為什麼停在大約 5 m」：機首轉到約 90°（正橫風）時前向風分量歸零。

### 3.4 原始碼佐證（有限度）

本 repo 內的 ArduPilot SITL 原始碼副本
`runs/artifacts/AIRFRAME_SIM_MODEL/s1b/review2/tree_3deee9c/`：

* `SIM_Aircraft.cpp:787-803` 的地面分支註解寫明 **"zero roll/pitch, but keep yaw"**，
  而且 `dcm` 的旋轉在這道夾制之前就已經被本步的氣動力矩積分過 ⇒ **在地面上偏航是自由的**，
  §3.3 的風標行為與原始碼一致。
* 偏航力矩 `na = qbar*b*(c_n_0 + c_n_b*beta + …)`（`SIM_Plane.cpp:350`），
  `beta = atan2f(velocity_air_bf.y, velocity_air_bf.x)`（`SIM_Plane.cpp:484`）。
  純順風時 `velocity_air_bf = (−W, 0, 0)` ⇒ `beta = atan2(0, −W) = +180°`（atan2 的分支割線），
  是 `beta` 的最大值 ⇒ 偏航力矩最大。純橫風（270° 的那幾格）是 `beta = −90°`，只有一半。

## 4. 我**無法**支持的部分（明說）

1. **前爬的速度量級沒有從原始碼推導出來。** 上述快照的 `SIM_QuadPlane.cpp:34` 把
   `ground_behavior` 設成 `GROUND_BEHAVIOR_NO_MOVEMENT`，該分支每一步都把
   `velocity_ef.x/.y` 歸零 ⇒ 照這份原始碼，飛機**根本不應該平移**。實測到的行為
   （只有機體前向、側向為零、偏航自由）比較像 `GROUND_BEHAVIOR_FWD_ONLY`
   （`SIM_Plane.cpp:84`、`SIM_Aircraft.cpp:806-845`）。
2. 我**沒有辦法證明**正在跑的 `sitl/ArduPlane.exe`（2026-04-07、10 930 117 B、
   sha256 `dec596c8…f0913`）是由那份快照建置的，也沒有在 `--defaults` 鏈上找到
   `SIM_GND_BEHAV`（預設 −1＝不覆寫）。所以「走的是哪一個地面分支」這一層仍未定。
3. **IMU 比力沒能當成證據。** dataflash 只從解鎖那一刻才開始寫，而那時前爬已經停了
   （§3.3），所以停機視窗量到的 `IMU.AccX/AccY` 中位數是 −0.001/−0.001 m/s²（水平合量
   0.0014 m/s²）＝沒有水平比力。這與「已經停住」一致，但**不能**用來檢驗前爬期間的受力。
4. 因此：**方位角已經解釋完畢**（弧的弦；東向分量不是另一個力），
   **偏航已經解釋完畢**（風標，且與原始碼一致），
   但**平移的來源分支**仍是未解。要解它需要在 SITL 上做一次受控探針
   （例如 `SIM_GND_BEHAV` 掃描，或把 `LOG_DISARMED` 打開重飛一次），本 label 沒有做，
   因為任務限定只飛兩趟。

## 5. 為什麼 270° 的架次沒有這個問題

同一支閘門、同一份程式、同一組起飛站量到的位移：

| trial | 模擬風 | 位移 (m, A1/B2/B3) | 方位角 (°, A1/B2/B3) | 容差 |
|---|---|---|---|---|
| `HV4W00` | 0 | 0.022 / 0.022 / 0.030 | 181.4 / 180.0 / 221.7 | 2.0（預設） |
| `HV4W05` | 5 @ 270 | 0.134 / 0.183 / 0.215 | 99.6 / 90.0 / 87.0 | 2.0（預設） |
| `HV4W55` | 5 @ 270 | 0.134 / 0.183 / 0.215 | 99.6 / 90.0 / 87.0 | 2.0（預設） |
| `HV4W55R` | 5 @ 270 | 0.134 / 0.183 / 0.215 | 99.6 / 90.0 / 87.0 | 2.0（預設） |
| **`HV4W55S`** | **5 @ 180** | **5.015 / 5.070 / 5.118** | **44.3 / 43.9 / 43.5** | **6.0（明示覆寫）** |
| `BEAMIDP1` | 0 | 0.022 / 0.022 / 0.030 | 181.4 / 180.0 / 221.7 | 2.0（預設） |

無風的兩趟位移 0.022–0.030 m，就是 1e-7 度（約 1.1 cm）座標量化的量級 ⇒ 是雜訊底。

270° 對機首朝北的停機是**純橫風**：相對氣流落在機體 y 軸上，而地面模型把機體側向
運動歸零；且 `beta = −90°` 的偏航力矩只有 `+180°` 的一半。位移方向（87–100°，正東）
與氣團移動方向（來向 270 ⇒ 吹向東）一致，但量值只有 0.13–0.22 m。兩件事都指向同一
結論 ——**只有帶順風分量的來向才會把飛機推出去**。三個 270° 架次（`HV4W05`、`HV4W55`、
`HV4W55R`，其中最後一趟是本 label 今天飛的）逐位元重現同一組 0.134/0.183/0.215 m，
支持「SITL 在此是決定性的」。

## 6. 閘門怎麼改的（`scripts/hv_sitl_run.py`，只在工作樹，未 commit）

* 新增 `HV_SPAWN_TOL_M`：**不給就是 2.0 m，行為與改動前逐位元相同**（已驗證：
  不設環境變數時 `SPAWN_TOL_M == SPAWN_TOL_DEFAULT_M == 2.0`，`HV_SPAWN_TOL_M=0`
  會直接 `SystemExit`）。預設值本身沒有被改。
* `spawn_readback.json` 新增 `tol_m` / `tol_default_m` / `tol_overridden` / `tol_source`
  四欄，終端在覆寫生效時印出 `⚠⚠⚠` 警告 ⇒ **不可能靜靜地放寬**。
* 逐機新增 `d_north_m` / `d_east_m` / `err_m_full` / `bearing_deg` 與解鎖前的
  `settle_trace`（時間、位移兩軸、機首、地速、空速、飛控自己的風估計）。
  這些**只記錄、不參與判定**。
* 新增 `pairwise`（規劃 vs 實得間距）與 `rigid_translation`（最大差、門檻 0.5 m）。
  **這一項不吃 `HV_SPAWN_TOL_M`**：容差被明示放寬時，它會升格為會擋飛的硬閘門
  （`enforced=true`），因為「規劃分站、SITL 沒分」正是會把間距打爆的那種不一致，
  放寬逐機容差擋不住它、但間距檢查擋得住。預設路徑不新增任何失敗模式。
* 6.0 m 這個數字的理由：大於量到的 5.118 m 有餘裕，但**小於 `spawn_spread_m = 10.0 m`**，
  所以「三架全部生在 HOME」那種故障（A1/B3 會差 10–20 m）仍然會被逐機容差擋下來。
