hv_dccpp/dubins.py:619-623
    def skip_k(s_m: float, R_m: float) -> int:
        """skip-k: k=ceil(2R/s) (spec 8.3). A (s=168.05, R=200) -> 3."""
        if not s_m > 0:
            raise ValueError("s_m must be > 0")
        return max(1, int(math.ceil(2.0 * R_m / s_m - 1e-9)))

hv_dccpp/decompose.py:689-693
    def _skip_sequence(n: int, k: int) -> list[int]:
        """fixed skip-k sequence (0, k, 2k, ..., 1, 1+k, ...)."""
        k = max(1, int(k))
        return [i for start in range(k) for i in range(start, n, k)]

hv_dccpp/platform.py:296-300   (R_eff -- also answers C6)
    def r_eff(self, wind_speed_mps: float) -> float:
        """R_eff(W) = max{R_plan, R_theo (1+W/Va)^2} (spec 3.2, D1; max curvature
        radius of the trochoid)."""
        w = max(0.0, float(wind_speed_mps))
        return max(self.turn_radius_planning_m,
                   self.turn_radius_theoretical_m * (1.0 + w / self.cruise_airspeed_mps) ** 2)

DEGENERACY (the real reason C3's feature never fired)
-----------------------------------------------------
_skip_sequence(n, k) == list(range(n))  i.e. IDENTICAL TO SEQUENTIAL, whenever k >= n.
  verified: k=5 -> identity for n=2,3,4,5 ; first differs at n=6 -> [0,5,1,2,3,4]
            k=3 -> identity for n=2,3     ; first differs at n=4 -> [0,3,1,2]
So the correct threshold is n > k, NOT "n >= 3".

CAN A SEQUENTIAL BASELINE BE FLOWN WITHOUT EDITING THE LIBRARY?
----------------------------------------------------------------
No config does it. planner.py:604-605 ranks the K-nearest candidates by t_add
(transition + operate TIME), so K=1 gives the greediest SKIP order, not a
sequential scan. legacy_mode only sets sweep_sequence="fixed" (estimator) plus
B=1 / lockstep / K=inf -- still cost-driven.
Two non-invasive routes exist, both needing a driver script (not a repo edit):
 (a) runtime monkeypatch of hv_dccpp.planner._candidates so `sel` sorts by
     geometric adjacency instead of t_add -> whole pipeline (energy, altitude,
     deconfliction, export) still runs -> a genuinely flyable sequential mission;
 (b) beam_idp(..., warm_start={uav: full sequential [(strip_id, dir)] list}) --
     warm_start is a FIXED PREFIX (planner.py:840,862-869), so a full-length one
     pins the entire tour. Main path planner.py:1491 does not pass warm_start,
     so this also needs a driver.
